## 15:13 Remote SSH half-open 연결 감지 구현

- **무엇/왜**: 네트워크 단절 뒤에도 SSH 프로세스가 살아 있어 원격 워크스페이스가 계속 `connected`로 표시되는 문제를 해결하기 위해, 장기 remote agent transport에 OpenSSH keepalive(`ServerAliveInterval=2`, `ServerAliveCountMax=1`)를 적용했다.
- **결과**: keepalive로 응답 없는 연결이 약 4초 내 process exit로 수렴하고, 기존 `session.disconnected` → `CONNECTION_CLOSED` 경로가 renderer의 `disconnected` 상태 전이를 처리한다. RED 테스트를 먼저 확인한 뒤 관련 테스트 37개와 전체 회귀 931개가 통과했고, 린트도 통과했다.

## 15:30 Remote disconnect 구현 리뷰

- **무엇/왜**: keepalive 구현을 correctness와 simplicity 두 관점에서 독립 검토해 사용자 AC, 상태 전파, 테스트 범위, 구현 형태를 확인했다.
- **결과**: Critical 1건과 Medium 3건을 발견했다. SSH multiplexing 환경에서 기존 master 연결을 재사용하면 active transport의 `ServerAlive*` 옵션이 실제 네트워크 연결에 적용되지 않을 수 있어 3~5초 AC는 아직 미충족이다. 추가로 end-to-end 단절 경로 테스트 보강, 중복 테스트 제거, 단일 사용 타입 별칭 인라인화가 필요하다. 리뷰 단계에서는 구현을 수정하지 않았다.
- **포인터**: [SSH 인자 구성](../../electron/remote-agent/ssh-utils.ts), [장기 transport 적용](../../electron/remote-agent/transport-ssh.ts), [transport 테스트](../../electron/remote-agent/transport-ssh.test.ts), [Remote IPC](../spec/remote-workspace/contracts.md)

## 15:41 Remote disconnect 리뷰 finding 수정

- **무엇/왜**: Critical 1건과 Medium 3건을 모두 닫기 위해 감시 대상 SSH transport의 multiplexing을 비활성화하고 테스트 및 구현 형태를 정리했다.
- **결과**: `-S none`으로 active transport가 전용 연결을 소유하게 했고, 실제 transport의 예상치 못한 process exit가 `RemoteConnectionService`의 `disconnected`/`CONNECTION_CLOSED` 이벤트로 이어지는 테스트와 renderer 상태 반영 테스트를 추가했다. 중복 인자 전용 테스트는 상태 전파 테스트로 교체하고 단일 사용 옵션 타입은 인라인했다. RED 중 renderer 배너가 오류 코드보다 사용자 메시지를 우선한다는 기존 계약을 확인해 assertion을 바로잡고 RED를 다시 관찰했다. 전체 회귀 931개, 린트, TypeScript 검사가 통과했다.
- **포인터**: [SSH 인자 구성](../../electron/remote-agent/ssh-utils.ts), [장기 transport 적용](../../electron/remote-agent/transport-ssh.ts), [transport/service 테스트](../../electron/remote-agent/transport-ssh.test.ts), [renderer 테스트](../../src/App.test.tsx)
